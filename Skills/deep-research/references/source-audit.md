# Source Audit

## Source Levels

### S 级

可支撑核心结论。

- 政府官网。
- 监管机构。
- 交易所公告。
- 上市公司公告。
- 法规原文。
- 官方统计年鉴。
- 企业官网正式披露。
- 招股书、年报、半年报、季报。
- 标准文件。
- 学术论文或权威研究机构报告。

### A 级

可支撑重要结论，重大数据仍建议交叉验证。

- 主流财经媒体。
- 行业协会。
- 券商研报。
- 咨询机构报告。
- 专利/标准数据库。
- 公开招投标文件。

### B 级

可作为事实线索或辅助论据。

- 企业新闻稿。
- 地方媒体。
- 行业媒体。
- 产品官网。
- 会议演讲材料。

### C 级

只能作为观点参考，不能单独支撑核心结论。

- 自媒体。
- 知乎专栏。
- 博客。
- 论坛。
- 未经核验的行业传闻。

### D 级

不得支撑核心结论。

- 经验估算。
- AI 推理。
- 用户未核验口径。
- 无法确认来源的数据。

## Citation Format

```text
来源: [标题](URL) | 发布日期: YYYY-MM-DD/未知 | 获取日期: YYYY-MM-DD | 级别: [S/A/B/C/D] | 口径: ...
```

## Fact Rules

- 关键事实必须尽量来自 S/A/B 级来源。
- B 级事实用于核心结论时，尽量有两个独立来源交叉验证。
- C/D 级来源只能作为观点或假设线索。
- 关键数据要标注统计口径、年份、适用范围。
- 无可靠来源时写：“缺少可靠公开数据，需进一步核验。”
- 数据冲突时列出冲突来源，说明可能原因，不得只选有利数据。

## Time Decay

- 政策法规：以最新发文为准，旧版标注已废止/已更新。
- 技术论文：1 年内高价值，2-3 年参考，3 年以上需确认未被推翻。
- 市场规模：优先最近年度，超过 2 年标注为历史数据。
- 公司信息：超过 6 个月需确认是否过时。
- 开源项目：Star、commit、release、issue 活跃度必须标注获取日期。

## Source Agent Checklist

source_agent 返回资料时必须包含：

- 来源标题。
- URL 或文件名。
- 来源等级。
- 发布日期。
- 获取日期。
- 抽取事实。
- 可靠性备注。
- 可直接放入参考资料的引用文本。
- 搜索状态：success / partial_success / failed。
- 来源缺口清单。
- 失败时的 `source_failure_log`。

## Technical Route Source Requirements

技术路线研究类任务必须启用 source_agent。高质量技术路线报告必须优先核验：

- IEEE Xplore。
- arXiv。
- ACM Digital Library。
- ISSCC。
- IEDM。
- Hot Chips。
- 相关公司官网。
- 专利数据库。
- 头部半导体公司白皮书或技术博客。
- 招投标、产业政策、投融资公开信息。

如果搜索失败，source_agent 仍必须输出：

- 来源缺口清单。
- 建议补充检索的数据库。
- 建议补充检索的关键词。
- 当前哪些技术结论不能作为最终决策依据。

## Forbidden

- 用 C/D 级来源支撑投资、合规、财务、政策、立项结论。
- 编造来源、日期、统计口径。
- 把多个来源的数据混用但不说明口径差异。
- 用“业内普遍认为”“资料显示”替代具体来源。
