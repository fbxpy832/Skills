# Source Audit

## Source Types

所有来源必须标注所属类型。类型决定来源的适用场景、默认级别和引用规则。

### 1. external_authoritative — 外部权威来源

定义：来自政府、监管机构、交易所、学术机构、国际组织等具公信力的官方发布渠道。

- `allowed_for_core_claims`: ✅ 是
- `default_level`: S — A
- 适用：政策、法律、监管、财务、统计、学术结论
- 规则：
  - 仍是事实断言，需标注发布时间、数据口径
  - 不同机构的统计口径可能不兼容，混用需说明
  - 权威来源 ≠ 当前最新，需核查时效性

### 2. external_media — 外部媒体与行业资料

定义：来自财经媒体、行业协会、券商研报、咨询机构、专利数据库等第三方机构。

- `allowed_for_core_claims`: ⚠️ 有条件 — 需标注视角偏差，核心结论需交叉验证
- `default_level`: B — C
- 适用：行业动态、竞争分析、市场对比、补充论据
- 规则：
  - 媒体有视角偏差（如券商对目标公司持股）
  - 企业新闻稿属营销材料，非独立事实
  - 咨询报告预测仅供参考，非确定结论
  - 不可把行业媒体单篇报道当行业共识

### 3. local_vault — 本地 Obsidian Vault

定义：用户本地 Obsidian Vault 中的笔记、文档、历史报告。

- `allowed_for_core_claims`: ⚠️ 有条件 — 仅补充业务背景，标注"内部口径"
- `default_level`: B — C
- 适用：内部业务背景、项目上下文、历史资料、专项上下文
- 规则：
  - 不是外部权威来源
  - 经营数据标注"内部口径，需核验"
  - 文件日期决定数据时效性
  - 个人笔记和会议纪要不是经过核验的事实

### 4. local_wiki — 本地技术知识库

定义：用户本地技术 Wiki，如 LLM Wiki、karpathy Wiki 等。

- `allowed_for_core_claims`: ❌ 否 — 仅用于技术原理解释和术语理解
- `default_level`: C
- 适用：技术原理、术语解释、分析框架启发
- 规则：
  - 不是最新事实来源
  - 不可用于判断最新论文结论、模型版本、产品状态
  - 不可作为技术选型唯一依据
  - Wiki 内容可能与最新进展有偏差

### 5. uploaded_files — 当前上传文件

定义：任务执行时用户明确上传的附件文件。

- `allowed_for_core_claims`: ⚠️ 有条件 — 优先读取，但需区分"文件内声称"与"已核验事实"
- `default_level`: 取决于文件类型
- 适用：当前任务最高优先级上下文
- 规则：
  - 文件内数据需标注"来源文件声称"
  - 文件可能有偏见、过时、不完整
  - 多文件间数据可能矛盾
  - 注意附件的免责声明（如"未经审计"）

### 6. model_reasoning — AI 推理判断

定义：模型自身的分析、归纳、判断、推理输出。

- `allowed_for_core_claims`: ❌ 否 — 不是事实来源
- `default_level`: D
- 适用：分析、归纳、判断、建议、逻辑连接
- 规则：
  - 必须与事实来源分开标注
  - 关键决策必须说明假设条件和置信度
  - 推理可能基于过时训练数据
  - 不可将"应该是"写成"实际是"

## Source Levels

来源按可靠程度分为 S / A / B / C / D 五级，与来源类型配合使用。

### S 级 — 核心依据

标签：`政府/监管/法规/交易所/统计年鉴/学术`

可支撑核心结论。最高可信度来源，但需确认时效性和口径。

- 政府官网
- 监管机构公告
- 交易所公告
- 上市公司公告（年报/半年报/季报/招股书）
- 法规原文
- 官方统计年鉴
- 企业官网正式披露
- 标准文件
- 学术论文（同行评审期刊）
- 权威研究机构报告

`support_capability`: 可单独支撑核心结论。

### A 级 — 强支撑

标签：`财经媒体/行业协会/券商研报/咨询报告/专利/招投标`

可支撑重要结论。重大数据建议交叉验证。

- 主流财经媒体（如 Bloomberg、Reuters、财新、经济观察报）
- 行业协会报告
- 券商研报（标注是否对目标公司有持股）
- 咨询机构报告（如 McKinsey、BCG、Gartner、IDC）
- 专利/标准数据库
- 公开招投标文件

`support_capability`: 可支撑核心结论，重大数据需 2+ 独立来源交叉验证。

### B 级 — 辅助论据

标签：`企业新闻稿/地方媒体/行业媒体/产品官网/会议演讲`

可作为事实线索或辅助论据。不可单独支撑核心结论。

- 企业新闻稿（标注"企业宣称"）
- 地方媒体
- 行业媒体
- 产品官网
- 会议演讲材料

`support_capability`: 需与 S/A 级来源配合，不可单独支撑核心结论。

### C 级 — 观点参考

标签：`自媒体/知乎/博客/论坛/未经核验传闻`

只能作为观点参考或灵感来源。不可支撑核心结论。

- 自媒体
- 知乎专栏
- 博客
- 论坛
- 未经核验的行业传闻

`support_capability`: 仅灵感/补充视角。若仅有 C 级来源，必须降置信度。

### D 级 — 假设/推理

标签：`经验估算/AI推理/未核验口径/无法确认来源`

不得作为事实呈现。仅可作为假设或推理线索。

- 经验估算
- AI 推理
- 用户未核验口径
- 无法确认来源的数据

`support_capability`: 仅假设。不得支撑任何事实性结论。报告中出现 D 级内容必须明确标注"假设/推理"。

## Citation Format

每条引用的完整格式：

```text
来源类型: [external_authoritative/external_media/local_vault/local_wiki/uploaded_files/model_reasoning]
来源: [标题](URL)
发布日期: YYYY-MM-DD / 未知
获取日期: YYYY-MM-DD
级别: [S/A/B/C/D]
口径: [统计口径/适用范围/备注]
```

示例：

```text
来源类型: external_authoritative
来源: [国家统计局 2025 年国民经济统计公报](https://www.stats.gov.cn/...)
发布日期: 2025-02-28
获取日期: 2026-05-05
级别: S
口径: 全年数据，规模以上工业企业，现行价格计算
```

## Fact Rules

### 级别门禁规则

| 规则 | 要求 |
|------|------|
| 核心结论 | 必须使用 S/A/B 级来源 |
| C 级来源 | 仅用于灵感/补充视角，不可支撑核心结论 |
| D 级来源 | 仅作为假设，永远不可作为事实 |
| 政策/法律/合规/财务 | 必须 S/A 级来源优先 |
| 仅 C/D 级来源可用时 | 降低结论置信度，标注"缺少可靠数据" |

### 交叉验证规则

| 验证组合 | 置信度 |
|----------|--------|
| 同一事实在 2+ 个 S/A 级来源中出现 | 高置信度 |
| S/A 级 + B 级来源 | 中等置信度 |
| 仅 B 级来源 | 标注"缺少独立交叉验证" |
| C/D 级或单一来源 | 标注"需进一步核验" |

### 数据规则

- 关键数据必须标注统计口径、年份、适用范围
- 不同统计口径的数据不得混用，混用必须说明口径差异
- 来源冲突时必须列出双方来源和数据，说明可能原因，不得只选有利数据
- 无可靠来源时写："缺少可靠公开数据，需进一步核验"
- 不可编造数据当可靠来源不存在时

### 表述规则

- 禁止使用"业内普遍认为""行业共识""资料显示"替代具体来源
- 禁止使用"数据显示"而不说明哪个来源的什么数据
- 不可使用"研究表明"而不列出具体研究
- 必须标注预测 vs 事实的边界（如"Gartner 预测 2026 年..."而非"2026 年市场将达到..."）

## Time Decay

### 时效性分级

| 类型 | 有效期 | 过期处理 |
|------|--------|----------|
| 政策法规 | 以最新发文为准 | 旧版标注"已废止"或"已更新" |
| 技术论文 | 1 年内高价值，2-3 年参考 | 3 年以上需确认未被推翻 |
| 市场规模 | 优先最近年度 | 超过 2 年标注为"历史数据" |
| 公司财务 | 优先最近季度/年度 | 超过 6 个月需确认是否过时 |
| 开源项目 | Star/commit/release/issue | 必须标注获取日期 |
| 新闻事件 | 事件发生时间 | 超过 1 年需确认后续发展 |

### 时效性检查项

- 是否引用了已废止的政策法规？
- 是否引用了已过时的技术论文（3 年以上未确认）？
- 市场/财务数据是否超过有效期？
- 所有网络来源是否标注了获取日期？

## Source Agent Checklist

source_agent 返回资料时必须包含：

| 序号 | 字段 | 说明 |
|------|------|------|
| 1 | 来源类型 | external_authoritative / external_media / local_vault / local_wiki / uploaded_files / model_reasoning |
| 2 | 来源标题 | 资料标题 |
| 3 | URL 或文件名 | 可追溯定位 |
| 4 | 来源等级 | S / A / B / C / D |
| 5 | 发布日期 | YYYY-MM-DD / 未知 |
| 6 | 获取日期 | YYYY-MM-DD |
| 7 | 抽取事实 | 从来源提取的关键事实 |
| 8 | 可靠性备注 | 视角偏差、是否经审计、数据口径等 |
| 9 | 引用文本 | 可直接放入报告的引用原文 |
| 10 | 搜索状态 | success / partial_success / failed |
| 11 | 来源缺口清单 | 未能获取的关键资料 |
| 12 | 失败时的 source_failure_log | 搜索失败原因和建议替代方案 |

## Per-Task Source Requirements

### business_decision — 公司经营决策类

- 核心财务/市场数据：**S/A 级必须**
- 行业分析：A/B 级
- 内部数据：local_vault，标注"内部口径"
- 禁止：C/D 级来源支撑决策结论
- 来源缺失时的处理：降低结论置信度，标注"缺少可靠公开数据"
- 如果仅有 C/D 级来源支撑某个关键判断，该判断必须标记为"待核验假设"

### government_report — 政府/国企汇报类

- 政策法规引用：**S 级必须**，引用原文，标注文号
- 统计数据：S/A 级
- 案例/试点：A/B 级，标注来源
- 禁止：C/D 级来源用于政策/法规/统计数据
- 禁止：编造政策文件名称、文号、发文单位
- 正式汇报稿中所有数字必须有迹可循

### technical_route — 技术路线研究类

- 技术事实（论文结论、产品规格）：**S/A 级优先**
- 技术分析/推理：可来自 local_wiki / model_reasoning，必须标注
- 必须启用 source_agent
- 优先核验来源：IEEE Xplore、arXiv、ACM Digital Library、ISSCC、IEDM、Hot Chips、公司官网、专利数据库、头部半导体公司白皮书/技术博客、招投标/产业政策/投融资公开信息
- 搜索失败时不得 PASS，输出离线初稿/待联网核验版，列出来源缺口清单和建议检索关键词

### investment_analysis — 投资/公司分析类

- 财务数据：**S 级必须**（年报/季报/交易所公告）
- 估值模型输入：S/A 级
- 行业空间/竞争格局：A/B 级
- 禁止：C/D 级来源用于财务数据、估值、投资建议
- 必须标注"不构成投资建议"
- 所有数字必须标注来源和统计口径

### general_research — 通用知识深度研究类

- 核心概念定义：A 级及以上
- 案例/趋势/观点：A/B/C 级可用，C 级需标注置信度
- D 级仅用于假设性讨论
- 争议点若仅有 C 级来源，不视为已确认争议

## Source Mixing Violations

以下为常见来源混用错误模式，发生任一情况即判定报告质量不合格：

| 错误模式 | 表现 | 纠正 |
|----------|------|------|
| 本地 Vault → 权威事实 | 报告中引用本地笔记数据但未标注"内部口径" | 标注来源类型和核验需求 |
| 本地 Wiki → 最新事实 | 用 Wiki 中的技术对比指导选型，但 Wiki 过时 | 外部搜索核验最新进展 |
| 模型推理 → 事实 | 报告中写"市场规模约 500 亿"但无来源 | 标注为推理假设，写明假设条件 |
| C/D 级 → 核心结论 | 用自媒体文章判断某公司财务状况 | 降为参考，寻找 S/A/B 级来源 |
| 搜索失败 → 照常输出 | 外部搜索失败但仍标"高质量正式版" | 降级为"离线初稿" |
| 混用口径 | 把两个不同口径的数据加总对比 | 标注各自口径，分别引用 |
| 编造来源 | 虚构或推测来源信息 | 写成"缺少可靠公开数据" |
| 匿名引用 | "业内普遍认为""资料显示""数据显示" | 写明具体来源和出处 |
| 预测当作事实 | "2026 年市场规模 500 亿"无预测方 | 写明"XX 机构预测"并标注预测性质 |
| 忽略时效性 | 引用 2022 年法规但已有 2025 年新版 | 核查最新版本，标注旧版状态 |
| 选择性引用 | 多个来源存在冲突，只引用对结论有利的 | 列出冲突双方，说明可能原因 |
| 口径混淆 | 国际口径与国内口径混用且不说明 | 分别标注口径和适用范围 |

## Forbidden

### 来源禁止项

- ❌ 用 C/D 级来源支撑投资、合规、财务、政策、立项结论
- ❌ 编造来源、日期、数据、统计口径、政策文号或文件名称
- ❌ 把多个不同口径来源的数据混用但不说明口径差异
- ❌ 用"业内普遍认为""行业共识""资料显示""数据显示""研究表明"替代具体来源
- ❌ 把 AI 推理（model_reasoning）写成事实
- ❌ 把本地笔记（local_vault）当外部权威事实引用
- ❌ 把本地 Wiki（local_wiki）当最新技术事实使用
- ❌ 把企业新闻稿当独立第三方事实
- ❌ 把预测/展望当已实现事实呈现

### 流程禁止项

- ❌ source_agent 搜索失败后仍输出"正式版"报告
- ❌ 仅有一个 C/D 级来源却作为核心依据写入报告
- ❌ 来源冲突时只选择对结论有利的数据而忽略反面数据
- ❌ 不标注数据时效性（发布时间、获取时间）
- ❌ 不标注数据口径却进行跨口径对比或加总
- ❌ 未对重大结论进行交叉验证即标注"高置信度"
